## Negative knowledge (established, not assumed)

- **`cargo test -p chronos-sandbox` does not rebuild `chronos-mcp`, and can report a false green.**
  `CARGO_BIN_EXE_chronos-mcp` is never set: Cargo only emits that variable for binaries declared in
  the same crate, and the binary lives in `crates/chronos-mcp`. The resolver therefore falls through
  to a target-dir path that builds nothing. A mutation applied to `decode_for_session` left the suite
  **passing** against a binary from an earlier build. Any green from this suite is only meaningful if
  `chronos-mcp` was rebuilt first.
  - Rejected fixes: `cargo build --dry-run` emits an **empty** diagnostic stream whether the tree is
    fresh or stale, so it carries no freshness signal. A real nested `cargo build` deadlocks on the
    target-dir lock the enclosing `cargo test` holds, surfacing as an `initialize` timeout. An mtime
    walk works but is a ~50-line heuristic over shared test infrastructure. **Left unfixed as a
    separate decision, not smuggled in.**
- **Sharing one server across `#[tokio::test]` functions is unsound, not merely inefficient.** Each
  test gets its own runtime; a server booted in test A has its stdio bound to A's runtime, which is
  dropped when A finishes. Booting one per test also exhausts the box — six concurrent boots produced
  spurious 120 s `initialize` timeouts that read as product failures.
- **A hand-written execution-log manifest is not a session that recorded events.** It parses, and
  discovery adopts it, but the log has no segments. Seeding must use the production writer
  (`SegmentedExecutionLog`).
- **An undecodable record fails the whole read closed rather than being skipped.** Seeding arbitrary
  bytes under an unknown payload tag makes the log unreadable, not empty — the poll errors out. Payloads
  must be real `TraceEvent`s under the canonical `"trace_event"` tag.
- **Response field names are `next_cursor`, `total_events`, `bucket_count`, `invocation_count`.** Not
  `cursor` or `event_count`; I guessed the latter two and the server corrected me.
- **`sandbox-smoke.yml` could never fire.** It filtered on `crates/chronos-sandbox/**`, and no such
  directory exists; the crate is a top-level workspace member. Fixed in `07d49e63`. This was
  pre-existing, not introduced here. `ci.yml` was unaffected: line 63 runs
  `cargo test --workspace --tests`, which does include the sandbox crate and my new E2E file.
