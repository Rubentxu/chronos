## Notes

- **Why per-cycle file categorization is dynamic**: each cycle's diff produces a unique mix of files. The backfill script reads `git diff --numstat base_sha..head_sha` and groups by category (`cc`, `index`, `cycle-artifacts`, `archive`, `change-entry`, `docs`, `scripts`, `rust`, `other`). When a category has > 8 files, the script shows a count rather than listing every path — keeps tables readable for high-file-count cycles (m9-41 has 71 files, m9-38 has 93 files).
- **CC#55 acceptance criteria**: accepts either the canonical `## Files Inventory` section OR a brief backfill note ("predates the canonical format" / "Files Inventory not recorded"). This lets older cycles (m9-11..m9-31) keep a pointer to their release-report.md without requiring a per-file reconstruction that would be inaccurate (the apply-checkpoint base_sha/head_sha can be reconstructed, but the commit chain sometimes spans merge wrappers that don't have a single linear diff).
- **Smoke test clone propagates working tree**: as discovered in m9-67, `git clone --shared` includes uncommitted changes. m9-68's smoke test additions are committed before the smoke test is re-run, so the cloned tree contains the CC#55 test setup. If a future cycle runs the smoke test with uncommitted vault changes, those will appear as drift; documented in handoff.
- **CC#55 vs CC#24 symmetry**: CC#24 (added by m9-32) watches for `## Cross-checks`. CC#55 watches for `## Files Inventory`. Both are python CCs auto-executed by CC#48. Both accept backfill notes for older cycles. The pattern of "introduce a section + add a CC that watches for it + accept-by-design for legacy" is now established.
