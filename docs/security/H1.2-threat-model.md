## 0. Why this document exists

Chronos is shipped as a single Rust binary (`chronos-mcp`) that exposes a JSON-RPC `stdio` transport implementing MCP (Model Context Protocol) for AI-agent consumers. The server can run three backends (`EbpfUprobe`, `PtraceAttach`, `BrowserProbe`) — each of which requires either kernel capabilities (`CAP_BPF` + `CAP_PERFMON`, `CAP_SYS_PTRACE`) or an external binary (`google-chrome` / `chromium` on `$PATH`). Three operational profiles follow from that:

- **local/stdio** — server invoked directly by a user-controlled AI client (Claude/Cursor/…) on the user's workstation. Privilege surface = the user's session.
- **Linux privileged capture** — same binary as `local/stdio`, but raised to a specific Linux-capability set to enable eBPF + ptrace attachment.
- **remote/multi-tenant** — **NOT IMPLEMENTED in this release.** Listed only so a future operator does not accidentally introduce it without a separate threat model.

Anything documented here that is not currently enforced in the code is recorded as a `gap` with an owner (`CapXxx`) so it can be tracked without being silently dropped. This document is **additive** (§0.4 of `AGENTS.md`); future cycles amend it without deleting sections.

## 2. Surface enumeration

### 2.1 Entry points

| Surface                          | Code path                                                              | Transport                                | Notes                                                                             |
|----------------------------------|------------------------------------------------------------------------|------------------------------------------|-----------------------------------------------------------------------------------|
| MCP server                       | `crates/chronos-mcp/src/bin/chronos-mcp.rs` (line 1–47)                | JSON-RPC over stdio (MCP `@rmcp`)        | Single entry point. `try_new` is fail-closed (line 33–39; if store cannot open the server exits 2 — never publishes a half-initialised state).|
| CLI library                      | `crates/chronos-cli` (no `src/bin/`)                                   | none                                     | Library only — no separate binary surface today. Out of H1.2 (no `bin/`).          |
| Sandbox client (out-of-process)  | `chronos-sandbox/src/client/tools.rs::McpTestClient::start`            | JSON-RPC over stdio, **spawns** `chronos-mcp` child process  | Test harness only; not part of the production surface. |
| Wire smokes `/tmp/g0.{1,2,4}-wire-smoke/` | heredoc'd `chrono-…-wire-smoke/` Cargo projects                       | JSON-RPC over stdio, manually invoked    | UAT/verification only; not deployed. |

### 2.2 Capabilities (typed surface already shipped)

Authoritative type: `chronos_domain::capability::Capability::as_str()` → `crates/chronos-domain/src/capability.rs:60–65`.

| Variant          | kebab-id         | Tool that activates it                       | Detection point                                            | Failure mode                              |
|------------------|------------------|----------------------------------------------|------------------------------------------------------------|-------------------------------------------|
| `EbpfUprobe`     | `ebpf-uprobe`    | `session_start{action=spawn}` with `condition.kind=uprobe` | `chronos-ebpf/src/lib.rs::EbpfAdapter::is_available` (line 126) — `check_availability` requires `CAP_BPF`+`CAP_PERFMON` and kernel ≥5.8 ring buffer support | emits `CapabilityUnavailable::EbpfUprobe` typed error |
| `PtraceAttach`   | `ptrace-attach`  | `session_start{action=attach}`               | `chronos-native/src/probe_backend.rs::is_available` (line 1089); tracer `chronos-native/src/ptrace_tracer.rs` uses `nix::sys::ptrace` (line 14) + `execvp`/`fork` (line 17) | emits `CapabilityUnavailable::PtraceAttach` typed error if `CAP_SYS_PTRACE` missing or uid mismatch |
| `BrowserProbe`   | `browser-probe`  | `browser_probe_start`                        | `chronos-browser/src/browser.rs:67` `Command::new(&chrome_path).spawn()` followed by typed `BrowserError::ChromeNotFound` if absent | typed error with the missing path                         |

The visibility of these capabilities is published to every caller as part of `CapabilitySnapshot` (`chronos-services/src/output.rs:2194–2217`) — including `tool_availability` and the `probed_at` epoch-ms timestamp for staleness checks.

### 2.3 Filesystem writes

| Path                                                | Produced by                                          | Restriction                                |
|-----------------------------------------------------|------------------------------------------------------|--------------------------------------------|
| `~/.local/share/chronos/store/` (default store root) | `ChronosServer::try_new()` opens redb store          | user's home, mode 0700 default; server refuses to start if store cannot open (`chronos-mcp.rs:33–39`).|
| `~/.cache/chronos/` (capability snapshot cache etc.) | capability-probe side effects                        | user's cache dir                           |

The binary performs **no writes outside the user's home and the user's standard cache dirs.** No files are written to `/tmp`, `/var`, or any system location. No `chmod`, `chown`, `setuid`, `setgid` calls exist in the production paths.

### 2.4 Process exec (other than the MCP server itself)

| Call                                                          | Code                                                                  | Context         |
|---------------------------------------------------------------|-----------------------------------------------------------------------|-----------------|
| `Command::new(&chrome_path).spawn()`                          | `crates/chronos-browser/src/browser.rs:67`                            | `BrowserProbe` only |
| `nix::unistd::fork` → `execvp` via `nix::sys::ptrace`         | `crates/chronos-native/src/ptrace_tracer.rs:14–17, 194–200`           | `PtraceAttach` only |

No other `Command::new`, no `popen`, no shell expansion of user input, no script execution.

### 2.5 Network exposure

`chronos-mcp` binds **no TCP, UDP, Unix-domain, or HTTP listener.** Confirmed by `grep -rn "TcpListener\|TcpStream\|UdpSocket" crates/chronos-mcp/src crates/chronos-cli/src` returns no hits (`MonotonicNs` is a unit type, not networking). Transport is strictly **stdio**, which is process-scoped to the parent that spawned the binary (AI client / test harness). A future `remote/multi-tenant` profile would require a separate threat model that this document does not anticipate.

### 2.6 Authentication

**No authentication layer** is present in this release. Because the transport is stdio, authentication is delegated to the OS process model: only the parent that has the file descriptors can talk to the server. If a `remote/multi-tenant` profile is ever introduced it must add authenticated transport, which is **explicitly out of scope** for H1.2.

### 2.7 Sensitive data handling

| Data class             | Where it appears                                                              | Handling                                   |
|------------------------|-------------------------------------------------------------------------------|--------------------------------------------|
| File paths of targets  | probe/attach parameters, log records                                          | stored verbatim in session; no redaction (the user's own paths) |
| Process command lines  | captured ptrace events (under `BrowserProbe` if Chrome child)                 | stored verbatim                            |
| Environment variables  | **never persisted;** only `RUST_LOG` is read in `chronos-mcp.rs:11–18`         | used for log filter only                   |

**Redaction** is **not implemented** in this release (`CapRedact` gap). For `local/stdio` the user has full filesystem visibility anyway, so leaking paths is acceptable in that profile. A future `remote/multi-tenant` profile would need to add redaction explicitly.

## 3. Threat catalogue (prioritised)

Each threat has: id, description, profile, attack vector, preconditions, mitigation current/future, residual risk.

### T-01 Process exec of attacker-supplied path via `chrome_path` override

**Profile:** `BrowserProbe` under `local/stdio`.
**Vector:** `browser_probe_start{chrome_path="/usr/bin/echo"}` followed by a subsequent probe configuration could (a) launch an unintended binary that the user believes is Chrome, (b) provide a stable exfiltration channel if `BrowserProbe` ever ships events to a remote endpoint.
**Preconditions:** attacker (or mistake) provides an explicit `chrome_path` in the request.
**Current mitigation:** (i) `chrome_path` is set by the user/operator locally and not exposed via environment variables, (ii) `BrowserError::ChromeNotFound` returns a typed error so the caller sees the actual path, (iii) capability check `BrowserProbe` already returns typed unavailability, (iv) the resulting Chrome is constrained via explicit `--disable-…` argv flags (`--no-sandbox`, `--disable-dev-shm-usage`, etc. — see `crates/chronos-browser/src/browser.rs:48–63`).
**Future mitigation (out of H1.2):** if a `remote/multi-tenant` profile appears, refuse `chrome_path` from untrusted sources or pin via an allow-list.
**Residual risk:** low for `local/stdio` (user controls parent). High if the profile is ever extended to multi-tenant.

### T-02 Privilege escalation through ptrace attach

**Profile:** `Linux privileged`.
**Vector:** `session_start{action="attach", pid=…}` could be invoked against a process running as a more privileged UID if `CAP_SYS_PTRACE` is granted beyond the user's needs.
**Preconditions:** caller has root or the right capability set.
**Current mitigation:** (i) `session_start{action=attach}` returns `CapabilityUnavailable::PtraceAttach` if the process cannot be attached (kernel returns `EPERM`), (ii) the typed error explains which capability is missing, (iii) we **do not** call `setuid` or `setgid` — the process keeps its original UID and `CAP_SYS_PTRACE` is granted externally (e.g. via systemd's `CapabilityBoundingSet=…`) **before** launch.
**Future mitigation (`CapPrivilegeDrop`):** add a `--drop-after-bind` mode for `local/stdio` to release the capability set once the snapshot is built.
**Residual risk:** medium — depends entirely on the operator's capability-bounding-set hygiene, which H1.2 cannot enforce.

### T-03 eBPF program injection (untrusted targets)

**Profile:** `Linux privileged`.
**Vector:** `observe{verb="create", condition.kind="uprobe", …}` could attach a uprobe to an unintended symbol if the user is tricked into authoring one. There is **no code-execution primitive** in this — uprobe fires a callback that records the event, it does not patch program flow.
**Preconditions:** `CAP_BPF` + `CAP_PERFMON` are granted.
**Current mitigation:** (i) `EbpfAdapter::is_available` requires kernel ≥5.8 ring buffer support and the `ebpf` feature flag (off by default in `crates/chronos-ebpf/Cargo.toml`); (ii) the uprobe hook only **observes**, it does not transform program state.
**Future mitigation:** enforce symbol-allow-lists per-language if H1.x adds them.
**Residual risk:** low — observation-only, mediated by the kernel.

### T-04 Filesystem-based denial-of-service via huge stores

**Profile:** all profiles with persistence.
**Vector:** A user (or unprivileged local actor) writes garbage to `~/.local/share/chronos/store`, prompting the server to allocate, fail to recover, or take a long time to open.
**Preconditions:** write access to the store path.
**Current mitigation:** `try_new` is fail-closed: if opening fails (corrupt store, lock contention, OOM), the server exits with code 2 and writes the failure to `stderr` (`chronos-mcp.rs:33–39`). The store is **not** partially migrated.
**Future mitigation (`CapStoreSchemaVersion`):** on open mismatch, refuse rather than `redb` upgrade — that already happens because the version is asserted in `ContentStore`.
**Residual risk:** low — recoverable by operator removing the store directory (provided operator, not the user running the server, is the one who can delete it).

### T-05 JSON-RPC message flooding (resource exhaustion)

**Profile:** all profiles with stdio transport.
**Vector:** Untrusted caller floods the parent process's `stdin` with large JSON-RPC requests.
**Preconditions:** the AI client is running in a context where another local actor can write to the parent's stdin. (Not possible in a hardened AI client; possible via a misconfigured test harness.)
**Current mitigation:** rmcp upper-bounds request sizes and uses Tokio buffers internally. No quota enforced **today** (`CapRateLimit`).
**Future mitigation:** add a token-bucket per session in H1.6+ if the `remote/multi-tenant` profile is built.
**Residual risk:** low for `local/stdio` (stdin is process-scoped to the AI client).

### T-06 Sensitive data exfiltration via session log

**Profile:** all profiles.
**Vector:** A user attaches a process whose commands contain secrets (env vars / DB passwords) and the events are stored verbatim.
**Preconditions:** user attaches a process that holds secrets in argv or env.
**Current mitigation:** none — events are stored verbatim. The user already had access to those secrets (they were the runner of the process), so this is not a privilege boundary breach, but a future `remote/multi-tenant` profile would re-classify it.
**Future mitigation (`CapRedact`):** add a configurable redact allow-list for command lines / env vars before events are persisted.
**Residual risk:** low for `local/stdio`; will become high for `remote/multi-tenant` and must be solved before that profile ships.

### T-07 Chrome process spawn pile-up

**Profile:** `BrowserProbe`.
**Vector:** Misconfigured client repeatedly calls `browser_probe_start` without `browser_probe_stop`, exhausting fd / pid tables.
**Preconditions:** buggy or adversarial client.
**Current mitigation:** server holds the `BrowserProbeSession` in a `Mutex<HashMap>` (`crates/chronos-mcp/src/server.rs:183–186`) and returns `BrowserProbeNotFound` on invalid IDs; `browser_probe_stop` is the only path that closes the underlying Chrome process.
**Future mitigation:** add an LRU / TTL for sessions without traffic in H1.6+ if needed.
**Residual risk:** low — Chrome processes are isolated to the user's UID; capped by `RLIMIT_NPROC`.

### 4.2 Profile `Linux privileged`

Adds, on top of OPS.1–OPS.8 of `local/stdio`:

| OPS  | Additional requirement                                                          | Status |
|------|----------------------------------------------------------------------------------|--------|
| OPS.1 | bounding set must contain exactly `CAP_BPF` + `CAP_PERFMON` + `CAP_SYS_PTRACE`   | **operator responsibility** (systemd `CapabilityBoundingSet=` or `setcap … cap_bpf,cap_perfmon,cap_sys_ptrace=ep …`). The server does **not** modify its own capability set. |

| OPS.7 | if upgraded, process is restarted with same capability set; re-establishing capability must be explicit. | `setcap` survives binary replacement as long as the inode is preserved; otherwise re-`setcap` is needed. |

Listed for completeness. **Must not be enabled** without a separate threat model, authentication layer, transport security, redaction (`CapRedact`), rate-limit (`CapRateLimit`), and multi-tenant isolation. None of those exist today.

## 5. Recommended operator setup for `Linux privileged`

```text
# Example systemd unit (informative; place at /etc/systemd/system/chronos-mcp.service
# only if you run chronos-mcp as a persistent process. For local AI-client use, you
# typically do NOT run it as a service.)

[Unit]
Description=Chronos MCP server (privileged capture profile)
After=network.target

[Service]
Type=simple
User=chronos
Group=chronos
# Limit the capability set to the strict minimum.
CapabilityBoundingSet=CAP_BPF CAP_PERFMON CAP_SYS_PTRACE
AmbientCapabilities=CAP_BPF CAP_PERFMON
# Deny network listening: no socket of type stream.
RestrictAddressFamilies=AF_UNIX AF_INET AF_INET6
# Read-only paths except the store and the cache.
ReadOnlyPaths=/usr /etc
ReadWritePaths=/var/lib/chronos /var/cache/chronos
# Resource limits.
LimitNOFILE=4096
MemoryMax=2G
CPUQuota=80%
# Lock-down hygiene.
NoNewPrivileges=yes
ProtectSystem=strict
ProtectHome=read-only
PrivateTmp=yes
PrivateDevices=yes
ProtectKernelTunables=true
ProtectKernelModules=true
ProtectControlGroups=true

[Install]
WantedBy=multi-user.target
```

Rationale of every directive is in `man systemd.exec` (`CAPABILITIES`, `RESTRICT_ADDRESS_FAMILIES`, `PROTECT_*`, etc.); the directives that map directly to OPS.1–OPS.8 here are:

- `CapabilityBoundingSet=`: OPS.1 + OPS.3 (privilege containment).
- `RestrictAddressFamilies=`: OPS.1 + OPS.3 (deny socket() families).
- `ProtectSystem=strict` + `ReadOnlyPaths=`: OPS.3 + OPS.5.
- `LimitNOFILE=`, `MemoryMax=`, `CPUQuota=`: OPS.4.
- `NoNewPrivileges=yes`: OPS.1 + OPS.3.
- `ProtectHome=read-only` + `PrivateTmp=yes`: OPS.3.

This unit file is **illustrative, not authoritative.** Actual deployment must be reviewed by the operator for their distribution; H1.2 does not replace it.

## 7. Out of scope (explicit)

The following are deliberately **not** in H1.2; they remain M1+ unless re-classified by a future roadmap cycle. The list is enumerative so omissions are visible.

- `remote/multi-tenant` profile (would require auth, transport security, redaction, isolation; see §4.3).
- `cargo-deny` / `cargo-audit` / `cargo-cyclonedx` integration (`CapSBOM`).

- `chronos-e2e` ptrace capture (env-locked, DEBT-G0-04).
- `chronos-native` lib parallel tests (env-locked `analytics_tools` flakiness, §6.5 of `AGENTS.md`).

## 8. Acceptance criteria (when H1.2 is declared `verified`)

The threat model is itself verified when **all** the following hold. These are the gate items; the corresponding cycle commit must include them.

1. **Document present.** `docs/security/H1.2-threat-model.md` exists, references `ROADMAP.md` + `CERTIFICATION.md`, and adopts OPS.1–OPS.8 verbatim.
2. **No silent lies.** Every fact in this document has either a code pointer (file + line) or a section of this document that explains it. No "should" claims that are not backed by code or by §5 systemd exemplar.
3. **Capability consistency.** The three `Capability::*` variants (`EbpfUprobe`, `PtraceAttach`, `BrowserProbe`) match `chronos-domain::capability` verbatim. Failure to match is a re-spin of the cycle.
4. **No file-system surprises.** A clean `grep -rn "TcpListener\|UnixListener\|UdpSocket\|http::Server\|tonic::Server" crates/chronos-mcp/src crates/chronos-cli/src crates/chronos-services/src` returns no hits. CI pipeline does not run this check today (`CapCIThreatgrep`, H1.6+).
5. **Fail-closed guarantee intact.** `chronos-mcp.rs::main` still exits `2` on store open failure. Verified in H1.2's verification block.
6. **Tag preserved.** After the merge, `git rev-parse v0.7.112^{}` continues to peel to `0be2ec2d` (per the §Git discipline in `AGENTS.md`).
7. **STATE.md updated.** A new `Estado de H1.2` row exists; `Estado`, `HEAD real observado`, `Última modificación de planificación`, `Próximas tareas`, `Siguiente paso inmediato` are updated.
8. **JOURNAL row appended.** A `2026-09-21 … H1.2 verified` row exists with evidence fields.

These criteria are checked once in the H1.2 verification and pinned there. Future amendments do not require re-validation.

## 10. Versioning

This document follows the additive policy §0.4 of `AGENTS.md`:

- New capabilities or profiles are **appended**, not edited.
