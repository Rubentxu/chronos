# ADR-0018 — M6.4 exportación opt-in de eventos compatibles y límites

**Status:** Accepted
**Date:** 2026-09-21
**Cycle:** M6 / M6.4 (exportación opt-in de eventos compatibles y límites)
**chronos HEAD:** `5a637905` (post M6.3 alignment).
**Spike location:** off-repo at **durable path** `/home/rubentxu/m6-spikes/m6.4-otel-exporter/`.

## 1. Context

ROADMAP §M6 §86 lists M6.4 as "exportación opt-in de eventos
compatibles y límites". The requirement has three pieces:

1. **Opt-in** — the caller decides which events are
   eligible for export. By default, nothing is exported
   (zero events until an `OptInFilter` matches).

2. **Compatibility** — the exported wire format must be
   OTel-shaped so that downstream OTel collectors can
   consume it without conversion. JSON Lines (one span
   per line) is the simplest portable format.

3. **Limits** — declared caps prevent the exporter from
   overwhelming the downstream:
   - `max_events_per_invocation` (per-invocation cap)
   - `max_events_total` (global cap per export call)
   - `max_field_chars` (per-string-field truncation cap)

This ADR delivers an `export()` function that consumes a
`CorrelationStore` (M6.3) + `events` slice + `OptInFilter` +
`ExportLimits`, and produces an `ExportResult` containing
JSON Lines + counters for each skip reason.

## 2. Decision

**Accepted.** The exporter is a single function:

```rust
pub fn export(
    store: &CorrelationStore,
    events: &[ChronosEvent],
    filter: &OptInFilter,
    limits: &ExportLimits,
) -> ExportResult;
```

`ExportResult` is:

```rust
pub struct ExportResult {
    pub lines: Vec<String>,                       // JSON Lines output
    pub emitted: usize,                            // total spans emitted
    pub skipped_probe_filter: usize,               // probe didn't match
    pub skipped_limit_per_invocation: usize,       // per-invocation cap
    pub skipped_limit_total: usize,                // global cap
    pub truncated_fields: usize,                   // fields truncated
}
```

### 2.1 Opt-in filter

The filter is a simple `Vec<String>` of allowed probe names.
`filter.allows(probe_name)` returns true if the probe is in
the list. `OptInFilter::empty()` allows nothing.

This is the **only** way to export events. There is no
`export_all()` API — the caller must explicitly opt in.

### 2.2 Limits

The `ExportLimits` struct has three fields with defaults:

| Field | Default | Effect |
|---|---|---|
| `max_events_per_invocation` | 100 | Hard cap per RecordedInvocation |
| `max_events_total` | 1000 | Global cap per export call |
| `max_field_chars` | 1024 | Per-string-field truncation |

Limit priority (checked in order):
1. `filter.allows(probe)` — if false, skip (counter: `skipped_probe_filter`).
2. `per_inv_count >= max_events_per_invocation` — skip (counter: `skipped_limit_per_invocation`).
3. `result.emitted >= max_events_total` — skip (counter: `skipped_limit_total`).
4. Field truncation — long strings get `…(truncated, original→limit)` suffix (counter: `truncated_fields`).

### 2.3 Wire format

Each emitted span is one JSON object on its own line.
Field order is fixed:

```json
{
  "trace_id": "4bf92f3577b34da6a3ce929d0e0e4736",
  "span_id": "0000000000000000",
  "name": "chronos.event.tool_call",
  "start_time_unix_nano": 100000,
  "chronos_invocation_id": "2ac6069c-ef4f-471f-810a-36c0c088eb21",
  "attributes": [
    {"key": "value", "value": "42"},
    {"key": "probe", "value": "tool_call"}
  ]
}
```

`trace_id` is the W3C hex form (32 lowercase hex chars,
no dashes). Internal-only invocations emit all-zero
`trace_id` (`00000000000000000000000000000000`).

`span_id` is derived deterministically from `event_idx`
(via `SpanId::from_bytes(event_idx.to_be_bytes())`).
This makes spans reproducible across re-runs of the
same event stream.

`start_time_unix_nano` is `ts_micros * 1000` (with
saturation on overflow). The OTel canonical unit is
nanoseconds since the Unix epoch; we use stream-relative
microseconds converted to nanoseconds (the stream
producer is responsible for setting the epoch).

`chronos_invocation_id` is the chronos-specific UUID
hyphenated form. This is **not** standard OTel — it's a
chronos extension that downstream consumers can use to
correlate back to chronos internal state.

`attributes` is a list of `{"key": "...", "value": "..."}`
pairs (the OTel common attribute encoding). Values are
**always strings** in the output (Int → `i.to_string()`,
Bool → `b.to_string()`, DomainRef → `ref:{name}`). The
typed nature of `EventField` is preserved chronos-side;
the export converts to string for transport.

### 2.4 JSON escaping

All strings are JSON-escaped: `\\`, `\"`, `\n`, `\r`,
`\t`, `\b`, `\f`, and `\uXXXX` for control chars below
`\x20`. This is necessary to keep the JSON Lines format
valid when event fields contain quotes, newlines, or
special characters.

### 2.5 Internal-only events

For invocations without an external trace context, the
emitted `trace_id` is the all-zero string. The
`chronos_invocation_id` is still emitted, so the
downstream consumer can still correlate back to chronos.
This is consistent with the M6.3 design: events without
external context still have a single, unambiguous
internal correlation.

## 3. Behavioural spec

### 3.1 Event ordering

Events are exported in `event_idx` ascending order,
grouped by InvocationId (using `BTreeMap<Uuid, Vec<u64>>`
for deterministic output). Within an InvocationId, the
first `max_events_per_invocation` events are emitted
(skipped counter reports the rest).

### 3.2 Probe name in output

Every emitted span has `attributes` containing a
`{"key": "probe", "value": "{probe_name}"}` pair. This
makes the output self-describing — the consumer doesn't
need to know what probe each span came from.

### 3.3 Empty filter

`OptInFilter::empty()` allows nothing. This is the
default state of any new filter; the caller must
explicitly add probes.

### 3.4 No silent defaults

Every skip reason has its own counter. The caller can
inspect `ExportResult` to know exactly why an event was
skipped. There is no `export_or_default` or similar
that silently emits something else.

## 5. Why this matters for M6

M6.4 closes the **export pipeline** that the rest of M6
builds on:

- **M6.5 (security/redaction)** applies to the JSON
  output before transmission. The exporter emits raw
  events; redaction is downstream. The separation keeps
  the exporter pure (no redaction policy).
- **M6.6 (UAT-M6-01/02)** spins two services and uses
  M6.4 to export both. The exporter proves the wire
  format is consumable.
- **M6.7 (gates)** verifies that round-trip
  `ingest → bind → export` preserves correlation: a
  span exported from one service must be correlatable
  back to its origin via `chronos_invocation_id`.

## 6. Out-of-scope / future work

- **No OTLP/HTTP collector**. The spike emits JSON
  Lines to stdout. Production would POST to an OTLP
  collector over HTTP/protobuf.
- **No batching**. Each export call is one batch; the
  caller decides frequency. Production would batch
  events across multiple invocations.
- **No retry / persistence**. If the collector is down,
  events are lost. Production would add a queue +
  retry layer.
- **No cardinality limits**. The exporter doesn't
  enforce a cap on distinct attribute keys. M6.5
  (cardinality) is the right place for this.
- **No parent-child spans**. Every emitted span is a
  first-class span (no `parent_span_id`). M6.5+ could
  add this when threading is needed.
- **No time stamp re-basing**. The exporter uses the
  raw `ts_micros` from the stream. Production would
  convert to Unix-epoch nanoseconds.

**M6 §M6.4 is delivered.** The exporter emits OTel-shaped
JSON Lines from a `CorrelationStore`, with caller-driven
opt-in and declared limits. 16/16 cargo tests pass in
0.00 s, plus a live JSON Lines smoke that produces
valid OTel output.

The spike is **path-dep** on M6.1, M6.2, M6.3 (all at
the durable `/home/rubentxu/m6-spikes/` location — NOT
scratch, which is periodically cleaned). It can be lifted
into chronos-core as a submodule when the M6 chapter

`export(store, events, filter, limits) → ExportResult` —
is what M6.5, M6.6, and M6.7 will all consume.
